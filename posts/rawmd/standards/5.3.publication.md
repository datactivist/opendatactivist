## 5.3 - Traduire le standard en langage technique et le publier

L'équipe projet est en charge de traduire les choix opérés sur les champs et valeurs dans un langage technique. L'utilisation d'un standard technique (Table Schema, JSON Schema, etc.) permettra de valider la conformité des futurs jeux de données aux normes imposées par le standard.

### Choisir un format de données

Le schéma, c'est la version numérique du standard — sa version lisible par les machines. Il en existe deux principaux. 
Le Table Schema est adapté aux données tabulaires (CSV) : chaque ligne représente une entité, chaque colonne un attribut. Il est utilisé dans la majorité des cas. 
Le JSON Schema convient aux données plus complexes ou hiérarchisées, mais demande des compétences techniques plus avancées. Surtout, la production de données au format JSON n'est pas accessible à tout le monde. 

En cas de doute, l'équipe de schema.data.gouv.fr peut aider à arbitrer. 

#### 👉 [Ressource clé : la documentation schema.data.gouv.fr](https://schema.data.gouv.fr/contribuer.html)

### Construire le schéma de données

La construction du schéma s'appuie sur le tableau de documentation des champs (section 5.1) : chaque colonne du tableau (nom, obligation, type, valeurs possibles, exemple) correspond à des propriétés du schéma technique. 

La validation demande des tests avec des jeux de données réels : vérifier que des données conformes sont effectivement valisée, et que des données non conformes sont rejetées avec des messages d'erreur clairs. 
L'équipe de schema.data.gouv.fr peut accompagner cette étape.

#### 👉 [Ressource clé : le guide qualité data.gouv.fr](https://guides.data.gouv.fr/publier-des-donnees/guide-qualite/maitriser-les-schemas-de-donnees)

### Publier le schéma de données, sa documentation et un jeu de données d'exemple

La publication sur schema.data.gouv.fr passe par GitHub. Un dépôt dédié est créé avec le schéma, sa documentation en markdown, et des exemples de données. L'équipe Etalab valide le tout avant publication officielle.

Un jeu de données d'exemple est utile pour que les producteurs comprennent concrètement ce qui est attendu d'eux. Il peut être fictif.

#### 👉 [Ressource clé : la marche à suivre schema.data.gouv.fr](https://schema.data.gouv.fr/contribuer.html)

### Présenter publiquement cette V1 du standard de données

C'est le moment de célébration 🎉 — mais aussi de test grandeur nature. En voyant le standard présenté dans son ensemble, des acteurs qui ont suivi de loin peuvent soulever de nouveaux points. Prévoir une V1.1 rapide pour intégrer ces derniers retours est une bonne pratique.

Une étape importante est franchie, mais il reste encore beaucoup de travail. Un schéma publié mais par utilisé n'aura pas d'impact : c'est dans la mise en oeuvre et la maintenance du standard que tout (ou presque) se joue.
