## 3.1 - Étudier les données existantes

Comparer les jeux de données permettra de déterminer un "plus petit dénominateur commun", c'est-à-dire les champs et valeurs partagées, qui seront sans doute incontournables dans le futur standard. 

### Dans une base de données : rassembler des jeux de données issus de plusieurs sources  
Une première étape consiste à créer un **document central**, qui servira de référence tout au long du processus de création du standard. Ce "master document" permettra dans un premier temps de rassembler, comparer et analyser des données existantes sur le sujet traité. 

Idéalement, utilisez une base relationnelle (de type airtable table ou grist - solution open source et gratuite). Cela permettra de structurer au mieux l'information. 
Cette base pourra par exemple contenir des tables : 
* **Sources de données** : Cette table recense les jeux de données sur lesquels vous allez travailler. Elle contient le nom du jeu de données, du producteur, la zone géographique et/ou temporelle concernée, l'URL du jeu de données et de sa documentation, et éventuellement d'autres champs permettant de le contextualiser. 
* **Champs** : Cette table constitue l'inventaire exhaustif des champs présents dans toutes les sources de données. Pour chaque champ, il est important de noter : nom exact, type (texte libre, valeur contrainte, date...), description, caractère obligatoire ou non. Une liaison doit être faite avec la source de données. 
* **Groupes de champs** (voir détail ci-dessous) : Cette table permet de regrouper des champs proches (selon leur fonction ou leur objet). Par exemple, tous les champs liés à la localisation d'un lieu (adresse, code postal, ville, coordonnées GPS...) seront regroupés dans un champ "Localisation". Ce travail de regroupement peut être fait en s'appuyant sur une IA, mais il est impératif d'effectuer un contrôle humain pour s'assurer que le rapprochement conceptuel entre champs est cohérent.  
* **Valeurs** (voir détail ci-dessous) : Cette table recense les valeurs utilisées dans les champs à listes contraintes. Elle est essentielle pour comprendre comment les différents producteurs décrivent des objets, et selon quelle granularité. Par exemple, si vous travaillez à standardiser des données relatives à des lieux offrant des services, avoir une liste exhaustives desdits services est essentielle. Dans le processus de standardisation, des choix seront opérés sur la base de la liste de valeurs que vous aurez établies lors de cette phase d'analyse (ne la négligez donc pas !).

### Identifier les champs en commun/proche (table "groupes de champs) 

Une fois tous les champs inventoriés, vous allez menez un travail de regroupement conceptuel. 
Concrètement, il s'agit de rapprocher dans un même "groupe de champs" des champs qui ont : 
* un nom proche (ex : description, description_courte, description_longue...)
* décrivent une réalité proche (ex : les champs adresse, rue, ville, latitude, longitude concernent tous la localisation d'un lieu / gratuit, payant, sur adhésion, sur conditions concernent les modalités d'accès)

Ce travail pourra nécessité l'appui d'experts métier, qui connaissent le domaine et peuvent valider les rapprochements les plus complexes, à propos desquels les experts data peuvent avoir des doutes.  

### Pour ces champs, identifier les valeurs communes/proches (table "valeurs)

L'analyse des valeurs permettra de révéler de manière fine les pratiques actuelles des producteurs de données. 
Pour les champs à valeurs restreintes identifiés comme prioritaires, il faut procéder à un inventaire exhaustif des valeurs utilisées par chaque producteur. Cette étape permet de comprendre comment les différents acteurs catégorisent et qualifient leurs données.
Par exemple, les producteurs de données sur les lieux de médiation numérique utilisent des listes de valeurs pour décrire les services, ou les publics, avec des niveaux de détail très différents. 
Mettre à jour des convergences ou au contraire (et surtout !) des divergences dans la mise en données est essentielle en vue d'effectuer des arbitrages. 
Un point d'attention cependant : cette analyse de l'existant donne des pistes pour la suite du travail, car il révèle des pratiques et contraintes. Mais ce n'est pas parce que certaines valeurs sont utilisées à date par une minorité d'acteurs qu'elles ne devront pas figurer dans le futur standard (car ces valeurs peuvent potentiellement répondre à des usages. Mais n'allons pas trop vite : on vous parle de l'importance de cette réflexion sur les usages dans la prochaine section). 

En bref, ce travail de fond sur les données est certes chronophages, mais il est impératif afin d'orienter les futurs arbitrages (faits en ateliers et/ou en copil).
